# AutoSentinel AI: Cleanup Report

## Scope and decision

The repository was inspected before editing. The current worktree was already
dirty: application modules/tests and README/configuration files are modified;
HCRL scripts, HCRL tests, an OpenRouter helper and the `datasets/hcrl/` captures
are untracked; `rag/retriever.py.bak` is already marked deleted. These changes
were treated as user-owned. No existing source, dataset, model, report,
configuration, cache, virtual environment or deleted file was removed or
restored in this audit.

The requested documentation was added under `docs/`. **No cleanup candidate
met the safe-to-remove standard**, so no files were removed. This is
intentional: reducing the number of files was not prioritized over preserving
functionality, benchmark reproducibility or local user data.

## Documentation findings that affect maintenance

- The HCRL code and data are present locally but are not tracked in Git. The
  model is ignored by `.gitignore`; captures appear as untracked files.
- The training command writes the HCRL model and evaluation report. It was not
  run during cleanup because it would retrain and overwrite existing artifacts.
- The HCRL demo reads the existing model and writes report/JSON outputs. Existing
  outputs were preserved; validation should direct any generated output to a
  temporary directory.
- The dashboard implementation archives distinct reports when history APIs
  are accessed. Some existing README text still describes report history as
  unavailable; the current dashboard source was treated as the implementation
  authority in the new architecture guide.
- `reports/project_audit.md` is a prior audit, not a source module, and contains
  observations that no longer match current provider/dashboard code. It was
  retained as historical material rather than overwritten.

### Checks not run and limitations

- The HCRL training command was **not executed**. It is designed to retrain
  and overwrite the selected model/report paths; avoiding that was required to
  preserve the existing model. Its help, imports and HCRL training unit tests
  were run instead.
- The default live CAN capture was **not executed**. The current environment
  is Windows and does not provide the Linux SocketCAN `vcan0` interface.
  `main.py --help` and mocked main/workflow tests passed.
- The dashboard was tested through its Flask test client and route/parser
  suite; a long-running web server/browser session was not started.
- No live Gemini or OpenRouter request was made. Provider tests use mocks.
- Artifact hashes were computed without a trusted manifest; the verifier
  explicitly warns that hashes alone do not prove source authenticity.

No test was removed or altered to obtain these results. The only files added
by this task are the four requested documentation files; no runtime source,
model or dataset was changed.
